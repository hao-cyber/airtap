# Airtap beta.4 验证与交付计划

状态：本轮六项有界技术门槛已通过。最终 APK 为 beta.4 / code 28，汇总见[交付验证](results/beta4-delivery-20261026.json)。下文保留原定门槛、真实结果、人工帮助及未验证范围；不将本轮技术完成扩大为任意设备、任意 AI 或独立普通用户验收。

## 本轮范围

本轮完成个人 AI 直接调用 HTTPS 的私有故障反馈闭环、手机上的报告管理，以及受影响的安装和设备操作回归。个人 AI 根据用户已有授权选择必要信息并脱敏，Airtap 提供私有接收、鉴权、访问隔离、删除和到期清理。用户无需另装插件、注册 GitHub 或回到手机重复确认已授权的反馈。

反馈附件和 MCP 封装是可选扩展，不作为本轮必须交付的前提，也不写成永久禁止。不会自动把报告公开到 GitHub。服务端不再调用另一个模型判断用户内容，不承诺自动脱敏能识别全部私人信息。

当前暂无独立真人试用者。本轮已完成维护者执行的正式 APK 空状态首用，以及实际 Muse 在小红约 75 分钟静置后的任务；维护者、协作 AI、模拟器均不能冒充陌生用户。缺少独立用户样本单独记录，不据此无限扩大技术任务。

## 统一证据口径

- 每份记录绑定 Android 版本与完整 APK SHA256、签名、CLI／接入说明及服务版本、设备／系统、执行者、时间和人工帮助；后续修改影响行为或制品字节时重验对应项。
- 使用合成故障描述、占位账号和专用测试报告，不为验收上传真实截图、聊天、密码或接入凭据。原始设备画面和运行凭据只保留在私有证据目录；公开报告只含必要摘要。
- 每项使用“待执行／通过／失败／被阻塞”。保留第一次失败、具体修复、重试与剩余问题；HTTP 成功、按钮点击或服务在线不能单独证明完整任务成功。
- 源码／合成设备测试、正常系统界面首用、真机维护验收和个人 AI 任务分别列证据。未变化的既有能力可引用对应旧记录，不改写旧版本结论。

## 反馈合同与隔离检查

接口合同已按[反馈说明](feedback-design.md)实现并在上述记录中验证。下表保留本轮行为要求；在线存储的 30 天保留期与 Cloudflare 平台恢复历史分别说明，不把在线删除称为所有副本立即消失。

| 主题 | 最小检查 |
| --- | --- |
| 个人 AI 与机主 | AI 只能读取／补充／删除本配对提交的报告；设备身份只管理本设备报告。A 的 AI／设备凭据不能查看或删除 B 的报告，已知报告编号也不例外。新配对不能自动继承旧 AI 的报告权限；机主在 AI 撤销后仍能管理本设备报告。 |
| 撤销 | 创建测试报告后撤销原配对，旧 controller token 的读、写、补充和删除均拒绝；重新打开 App 不自动恢复旧授权。反馈入口不得复用设备动作接口绕过撤销。 |
| 匿名回执 | 无配对故障可提交允许的合成材料；私有回执凭据不可枚举，报告编号本身不能作为读取或删除凭据。错误／缺少凭据和已到期回执不暴露内容。首次响应丢失后能以明确的幂等合同恢复，不能仅凭公开编号取回原凭据。 |
| 幂等与删除 | 同一身份、同一幂等键重复请求不产生第二份报告；冲突内容返回明确结果。删除后详情、列表、索引和回执不可再取得原内容；验证重复删除和迟到重复提交的合同，不能无意恢复已删除报告。本轮手机入口提供单份删除。 |
| 到期 | 保留期从明确时点计算，普通查询／状态更新不无限延长。时间推进测试同时覆盖读取时过期检查与后台实际清理；删除正文、索引和回执，不能只在 HTTP 层隐藏。使用可控时钟验证，不为 30 天保留期等待 30 天。 |
| 维护权限与凭据 | 管理员凭据只能从私有运维配置注入，不能进入 APK、CLI、接入说明、公共资产或 URL；错误和应用日志不打印 Authorization、请求体或凭据。错误管理员 token 拒绝，正确 token 仅取得维护合同允许的私有结果。 |
| 未公开与最小数据 | 默认无自动屏幕采集、无自动用户内容上传、无 GitHub 出站创建。AI 可提交有用的脱敏自由描述；不能宣称服务器验证了脱敏正确性，也不能把私有提交等同于公开授权。用包含指令式文字的合成报告确认只存作数据。 |
| 配额与失败恢复 | 校验体积、字段、频率及存储上限，拒绝结果明确；反馈超时／限流／服务不可用不会增加设备命令序号、撤销配对或重放任务动作。确认删除通道不会被报告创建配额阻塞。 |

若合同对报告归属、匿名回执恢复、删除后的幂等状态或保留期起点尚不明确，先修正实现合同再验收；这些属于反馈功能自身的完整性，不新增用户确认步骤。

## 正常首用与设备任务

空状态首用使用本轮最终正式包和独立模拟器。维护工具可搬运安装包、记录状态和截图，但必须通过系统安装器及权限页面完成安装与授权，不把 `adb install`、写设置或预置配对记成普通安装路径。没有出现的“受限设置”入口如实记未触发，不人为制造或假称已通过所有品牌引导。

按手机实际 App 目录选择一个最小跨 App 任务，例如在可用的系统应用完成一次明确操作，再在可保存内容的应用保存并离开、重开核对。结果必须来自手机界面；节点可以确认的任务无需强制看图，坐标操作必须实际查看对应截图。若所需 App 不存在，选择同等可核验的实际任务并记录，不能拿模拟响应当作手机任务。

随后创建一份专用测试报告，在手机正常界面读取与删除；验证 AI 后续取得的是已删除结果，再停止／撤销连接并检查旧凭据拒绝。反馈失败时仍需证明原有读屏或无害操作可以继续。

屏幕恢复只复验本轮受影响部分：查询状态不亮屏；有效授权的请求可按平台正常能力恢复；需要系统认证时明确本次设备命令未执行、未排队等待重放；认证后由 AI 新观察再决定操作。操作后的观察失败与前一动作执行结果分开。停止或撤销后不能因迟到恢复回调继续操作。

## 60 分钟后验与结束条件

小红的实际 Muse 验收由已获独占权的聊天执行，其他执行者不并发操作设备。保持已记录的 USB 供电和系统电池设置，不为延长静置而改变全局锁屏策略。静置期间避免用设备命令轮询干扰样本；必要维护读数、网络变化、人工唤醒和提前返回都要记录。

本次静置起点为北京时间 2026-10-26 15:18:59，实际 Muse 首次状态请求为 16:34:30，超过原定 60 分钟。实际任务、两张合成内容截图、反馈 JSON 与独立事后 APK／服务诊断已经核对，见[完整后验记录](results/beta4-muse-idle-20261026.json)。原始 status／observe 等设备 JSON 未进入共享包，按 Muse 脱敏摘录分类，不冒充全量原始日志。

静置结束后，Muse 使用已有私有连接先观察设备，再完成一项可核验的小任务。若真实 AI 的运行环境锁屏、登录或其他外部条件阻断，应记录具体阻塞，不用维护者 CLI 代做后标成 Muse 成功。恢复同一轮必要步骤即可，不自动扩成多日监控。

最终报告逐项回答：反馈闭环与隔离、正式包空状态首用、恢复回归、60 分钟实际 Muse 后验、发布取回分别是否通过；同时列维护帮助、未验证设备、未实现可选项及独立真人样本缺口。报告完成与设备任务完成是不同结果，不因收到报告编号就宣称问题已解决。
