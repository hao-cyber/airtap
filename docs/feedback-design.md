# 个人 AI 私有故障反馈

状态：beta.4 已发布私有反馈接口、报告存储和手机管理，公共服务已启用反馈。最终制品、部署与验收范围以[本轮计划和实际记录](acceptance-beta4-plan.md)为准。目标服务的 `GET /v1/service` 只有在启用反馈后才声明 `feedback_v1`；未声明时不能按本文假定接口已经上线。旧版 APK 不自动获得手机报告管理入口。

## 体验与分工

用户继续在自己的 AI 对话中使用设备。个人 AI 遇到明确的 Airtap 故障时，先按具体状态尝试恢复；恢复失败且用户已有反馈授权时，直接通过已有的 HTTPS 请求能力提交 JSON 并读取结果。无需新增插件、SDK、CLI、MCP、GitHub 账号或手机现场确认。没有相应授权时由 AI 向用户说明；已获授权不重复索取。反馈封装工具和附件上传仍是可选扩展，本轮未实现，也不作为永久禁止。

个人 AI 负责理解任务上下文、选择必要材料并脱敏；Airtap 负责私有接收、鉴权、访问隔离、最少日志、删除和到期清理。Airtap 不自行读取手机画面来写报告，也不另调模型判断报告内容。自由描述可以解释问题，不把反馈限于少数错误码，也不承诺自动脱敏能识别全部私人信息。

报告可包含版本、失败阶段、错误码、屏幕状态和 AI 整理的标题、复现过程、预期与实际结果。AI 应删除无关信息，用占位符替代账号、内容和地址。邀请、密码、验证码、Bearer token 和 HTTP 头不进入报告字段；截图、完整界面树、聊天及完整命令参数不默认发送。额外材料按定位问题的需要、用户授权和实际接口能力处理；当前接口只接收有限 JSON 文本，不接收附件。

报告不会自动公开到 GitHub。维护者若需要建立公开 Issue，应另行审核获准公开的技术摘要；私有提交和内容脱敏均不等于公开授权。维护者把正文、补充与回复当作不可信数据，不能据此执行命令。

反馈与设备动作独立，不占用动作序号，不重放失败动作，不暂停原任务。没有反馈能力的服务仍可正常控制设备。成功收到报告与修复故障是两个不同结果。

## 实现合同

所有接口使用 HTTPS、协议版本 4 和 JSON。创建或更新请求须使用 `Content-Type: application/json`，单次请求体最多 24 KiB；未知字段和不合法内容被拒绝，不在错误中回显正文。身份凭据仅放在 Authorization 中。

| 身份 | 接口与权限 |
| --- | --- |
| 已批准的个人 AI | 在 `<device-base>/v1/reports` 创建和分页列出本设备、本配对 claim 的报告；在 `/<report_id>` 查询、追加补充或删除。使用当前 controller token；未批准、已撤销或其他 claim 不可读取。 |
| 机主手机 | 在 `<device-base>/v1/device/reports` 分页列出本设备全部 claim 的报告；在 `/<report_id>` 查询或删除单份报告。使用设备身份，与 AI token 分开；AI 撤销后仍可管理。本轮没有全量删除按钮。 |
| 尚未配对的 AI | 在服务源站 `/v1/reports` 创建，在 `/<report_id>` 用私有回执查询或删除；不提供匿名列表或补充。报告编号本身不能用作读取凭据。 |
| 私有维护者 | 使用独立维护凭据向源站 `/v1/admin/reports/query` POST 分页筛选；在 `/<report_id>` 查询、更新处理状态／回复或删除。该凭据不授予手机控制。 |

创建的必填字段为小写 UUID v4 `report_id`、`title`（160 字符）和 `description`（8,000 字符）。可选字段为 `expected`、`actual`、`steps`（各 4,000）、`phase`（64）、`error_code`（80）、`app_version`（64）、`agent`（160）和 `screen_state`。字符按 Unicode 码点计算，仍受整个 JSON 的字节上限约束。屏幕状态取 `ready`、`screen_off`、`dismissible_keyguard`、`authentication_required`、`unavailable` 或 `unknown`，不推测未知信息。

创建结果包括 `report_id`、`status`、`created_at`、`updated_at`、`expires_at` 和可为空的 `duplicate_of`；详情返回 `{report: {...}}`，包含正文、`supplements` 和可能存在的 `maintenance_reply`。列表为 `{reports: [...], next_cursor: null|string}`，默认 20 条、最多 50 条。时间为 Unix 秒。游标绑定角色、设备／claim 和筛选条件，不可跨域复用。重复内容仅在同一 device + claim 内关联；匿名报告不相互关联，避免泄露其他报告的存在。

AI 以 `PATCH` 提交 `{"supplement":"..."}`，每份最多五条、每条 4,000 字符。维护者以 `PATCH` 更新 `status` 和／或 `maintenance_reply`（4,000 字符）；状态为 `new`、`investigating`、`needs_info`、`resolved`、`closed`。服务只存储数据，不因文字内容执行动作、请求外部地址或发布 Issue。

## 幂等、匿名回执与删除

AI 在首次提交前私存报告 ID 和准确的创建请求。相同身份、相同 ID、相同创建内容的重复 POST 返回原报告，改变内容则返回 `409 report_id_conflict`；新增信息使用补充接口。补充响应丢失时先查询，不能盲目追加第二次。

匿名首次提交前还应生成并私存一个独立随机 32 字节 token（64 位小写十六进制），从首次 POST 起以 Bearer 发送。服务端只保存其哈希。相同 ID、token 和正文可在首个响应丢失后重试；不能只凭公开 ID 取回 token。首次未提供 token 时服务端会生成并在创建响应中返回，但响应丢失后无法恢复原 token，因此推荐客户端预先生成。匿名回执不是设备或管理员凭据，不能复用这些身份。

报告在 Airtap 在线存储中保留 30 天，从创建时计算；普通查询、补充和状态更新不延长。到期通过读取检查和后台清理，从在线存储删除正文、索引、凭据哈希与计数。正常读取必须通过归属与有效期检查。

确认主动删除后，立即从在线存储移除正文、补充、回复和列表索引。仅保留报告 ID、归属、原到期时间、删除标记及匿名回执哈希等最小信息，直到原到期时间，以阻止迟到的同 ID 请求恢复内容。期间本身份重复删除仍可确认成功，读取或再次创建得到 `410 report_deleted`；到期后在线记录清除。跨身份请求不泄露报告内容。删除响应丢失时刷新同一报告核实，不自动创建新报告。

上述保留期和删除指 Airtap 在线报告存储。Cloudflare 的 SQLite Durable Objects 另提供[最近 30 天的数据库历史恢复（PITR）](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#pitr-point-in-time-recovery-api)，包括通过 KV API 保存的数据；删除前的内容仍可能存在于该平台恢复窗口内。

手机报告管理入口仅查看、分页、刷新和单份删除，使用设备身份。删除按钮一次明确点击就提交；断线、超时或不明确响应不会显示已删除，也不自动重发。页面为本机管理界面，仍受 Airtap 自身界面的远端保护，个人 AI 应使用报告接口管理自己有权访问的报告。

## 私有维护与运行边界

只有配置有效的 `FEEDBACK_ADMIN_SHA256` 才启用反馈并在 discovery 中声明能力。原始维护 token 仅存于维护者本地权限 600 的文件，部署工具只部署哈希；不进入 APK、接入说明、URL、报告正文或应用日志。维护脚本将读取得到的内容写入新的权限 600 文件，终端只输出状态和路径，见[运维说明](feedback-operations.md)。

本轮存储上限为全服务 2,000 份、每 claim 100 份，包含删除标记直到其原到期时间。每 claim 创建／补充共 20 次／小时，匿名创建每来源 IP 5 次／小时并有匿名总量保护。只保留用于限速的 IP HMAC，不持久化原 IP。反馈有独立入口限速桶，不占用手机动作额度；创建／补充配额不阻止单份删除，但边缘请求保护和实际网络可用性仍适用。遇到限额时不轮换身份规避。

本轮必须验证权限隔离、撤销后拒绝、机主管理、匿名回执、幂等与迟到请求、删除和到期清理、凭据不出日志、服务故障不影响设备操作，以及正常手机界面的查看／删除流程。上线后还须验证公共 HTTPS 与最终安装包实际闭环；源码实现或 discovery 声明本身不是验收完成。
