# AI 手机能力对照与 Airtap 扩展方向

调研日期：2026-11-12。Airtap 对照基线：Android code75 / 0.4.0-beta.45，CLI.22，源码 `8501cde`。

**多数通过手机 App 完成的日常任务，都可以作为 Airtap 的实现目标；不能由“能看屏幕、能点击”推导出所有 AI 手机功能已经可用。** 完成结果还取决于个人 AI 的规划、数据进出、事件触发、执行恢复、账号和系统接口。厂商的通话音轨、虚拟执行窗口、受保护数据与硬件能力，不会随安装一个普通 APK 自动获得。

这份调研覆盖代表性的厂商助手、开源手机 Agent 和任务评测项目。资料来自官方产品页、开发者文档和项目仓库；是能力地图，不是穷尽全网的普查，也不是对竞品的实机成功率测评。厂商页面中的能力仍受机型、地区、版本、账号和上线批次约束。

当前实现的逐项说明见[原子能力清单](../atomic-capabilities.md)，实体设备的最新结果见 [code75 个人 AI 实测](../results/beta45-code75-personal-ai-20261112.json)。下面的建议和候选任务均不能当作新增功能已交付或已通过验收。

| 多 AI 与多设备 | Muse、Instinct 轮流使用手机，接手知道做到哪里 | 已有多连接、互斥租约及历史交接验收；共享业务上下文并非自动完整同步 | 交接传任务目标、完成步骤和证据引用；不复制另一 AI 的长期凭据或所有私人记忆 |

| 位置、传感器与周边 | 到某地后执行、读运动状态、控制配件 | 地图与配件 App 可走 UI；没有统一 GPS、传感器、BLE、NFC 或 USB 配件协议 | 需要真实使用方再加适配；手机放家里时，它的位置与摄像头不是用户身边的位置与视角 |
| 智能家居与充电 | 电量高时停充，低时恢复，控制灯或插座 | 已有电池状态；可通过米家等已授权 App 操作，尚非实物闭环证明 | 智能插座/设备平台提供实际开关；需滞回阈值、断网兜底及充电状态回读，不把充电图标当成电气隔离证明 |
| 人与 AI 同时用屏幕 | AI 后台购物，用户前台继续聊天 | 当前控制默认屏幕，没有厂商级隔离虚拟窗口 | 闲置手机可避开抢屏问题；若做副屏/虚拟窗口，需要单独平台能力与输入隔离设计 |
| iPhone 与其他设备 | 同一个个人 AI 也能用 iPhone、平板、电视和 ESP32 | Android 手机是当前实测主线；不同设备不是同一 APK 的自然延伸 | 共享接入与授权概念，各自实现适配器和能力发现；不从 Android 通过推断其他平台通过 |

### 不能只靠增加权限解决的差异

- **电话音频不等于麦克风录音。** Android 对通话上下行音频有特权条件，普通应用获得 `RECORD_AUDIO` 并不等于拿到通话音轨。应用播放音频的采集还取决于音频用途及对方的捕获策略。[音频输入共享](https://developer.android.com/media/platform/sharing-audio-input)、[音视频采集](https://developer.android.com/media/platform/av-capture)。
- **通知不等于全量短信。** Android 15 对不受信任通知监听器的敏感通知内容有保护；短信应用是否显示、应用是否发通知和通知监听是否收到，需要分别判断。[Android 15 行为变更](https://developer.android.com/about/versions/15/behavior-changes-all)。
- **受保护窗口不等于树缺失。** 普通无树弹窗可以尝试新截图和视觉点按；系统明确保护的画面可能无法截图。不能将保护性空白截图标成成功观察。[Android 安全窗口说明](https://developer.android.com/security/fraud-prevention/activities)。
- **后台在线不等于可随时开相机或麦克风。** Android 的后台启动与使用中权限有独立限制；必须按当前设备条件设计启动和恢复。[前台服务启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)。
- **厂商后台执行窗口不是普通 APK 自带能力。** Gemini 的方案包含隔离虚拟窗口；当前 Airtap 的默认屏控制不具备这个条件。[Google 多步骤任务说明](https://blog.google/innovation-and-ai/products/gemini-app/android-multi-step-tasks/)。

这些是实现条件，不是给任务类别加一刀切的产品禁令。支付、通信、账号设置等仍按机主具体授权和真实系统流程执行；任何成功声明都须有最终状态证据。

## 3. 最值得先做的用户任务

以下是候选验收和演示场景，尚未在本轮执行。优先用已有原子能力组合，遇到实际缺口才加接口。默认使用测试数据、用户自有素材及已有授权；对外提交与交易依照对应任务范围处理。

| 场景 | 完整流程 | 验收看什么 | 当前最可能缺的部分 |
| --- | --- | --- | --- |
| 找远程兼职 | 在招聘 App 筛选标注/远程岗位 → 查看要求 → 去其他来源核对 → 整理匹配表 → 准备针对性申请 | 岗位来源、时效、地区/薪酬条件、用户真实经历相符；没有实际提交就不写成投递成功 | 长列表提取、上下文保存与跨 App 核对；不能承诺获得工作或收入 |
| 整理报销 | 从订单和票据 App 获取本人资料 → 按日期/金额分类 → 生成表格 → 保存附件 | 金额合计、订单与文件对应、可重开、重复运行不重复计入 | 文件导出/选择器差异、表格回传 |
| 同款比价 | 多平台查同规格商品 → 核对运费、优惠和售后 → 生成比较 → 按授权加入购物车或继续下单 | 规格一致、价格时间明确、实际购物车/订单状态；不能把列表价当成交价 | 动态页面与复杂优惠计算，结果未知时避免重复下单 |
| 制作并发布内容 | 搜集主题 → 用自己的素材制作 → 保存到手机相册 → 在目标 App 编辑 → 按授权保存草稿或发布 → 回读 | 素材可选择、文字图片对应、草稿/发布状态和目标账号正确 | 真实媒体交换、目标 App 的编辑流程；不能借用他人图片伪装个人体验 |
| 行程整理 | 读取本人订单/短信 → 核对航班酒店 → 地图查路线 → 建日程 | 日期、时区、地址与来源一致；日程保存重开不重复 | 日历稳定入口、事件去重 |
| 消息驱动办事 | 收到指定订单变更通知 → 查原 App → 更新计划或通知个人 AI | 事件确实触发、只处理一次、来源核实、撤销后停止 | 通知实机验收、个人 AI 的事件接入与后台任务入口 |
| 店铺日常协助 | 查本人店铺待处理事项 → 汇总 → 整理回复或处理任务 → 回读 | 订单/对象一致、动作有记录、未知结果先查后重试 | 业务流程的幂等与长任务恢复；依账号实际权限 |
| 设备自己维护 | 统计 App 与空间 → 安装/升级指定 App → 启动检查 → 整理布局 → 留下变更清单 | 空间变化、版本、可启动、保留账号与数据、最终布局可核对 | 桌面/OEM 差异和安装器恢复；卸载先按已授权名单 |
| 帮家里设备办事 | 电量/状态满足条件 → 操作已绑定智能插座 → 核对插座与手机状态 → 低电量恢复 | 实物状态、阈值滞回、断网后的恢复和异常提醒 | 真实插座、账号绑定、调度和失联兜底 |
| 看现场再行动 | 获取机主授权的相机照片或短录音 → AI 理解 → 生成记录或执行后续动作 | 实际采集文件可解码、内容与场景对应、无授权时不采集 | 相机/麦克风实体正例；实时视觉另算 |

优先选“找远程兼职、整理报销、制作内容”中的两项做完整演示，比继续增加计算器演示更能体现价值。首轮可以止于有用且可核对的结果；如果目标本身包含投递、发布或交易，则不能把草稿悄悄当成整个目标完成。

## 4. 扩展顺序与设计取舍

### 第一优先：完成已有能力的真实闭环

当前最明确的工作是完成通知、相机、麦克风和多日后台验证，并用已有接口完成少量有价值的真实任务。录屏已有真机文件，但请求 8 秒的成品播放时长为 11.372 秒；末帧补尾与真正停止时间要分开，不宣传精确 8 秒。失败记录和未验范围见 [code75 实测](../results/beta45-code75-personal-ai-20261112.json)。

这次调研不改动正在观察的手机、不重启网络或替换中继，也不把所有候选场景追加成现有发布验收的门槛。原有完成条件保持，实际发现的缺陷按影响处理。

### 第二优先：事件与任务能接得上

形成“设备事件 → 已授权个人 AI → 任务执行 → 结果回执”的明确链路：

1. 手机产生有来源、时间和游标的事件；保留当前有界缓存，明确缺口与过期。
2. 先接个人 AI 已有的定时任务/收件入口。没有事件入口的 AI 继续用明确的轮询，不把任意 webhook 等同于能唤醒任意 AI。
3. 把事件 ID、任务 ID 和租约关联起来；重连后先核对是否已执行，再决定是否重试。云端收到了事件，不等于手机动作成功。
4. 对排队、取消、抢占和交接定义简单状态。优先复用现有个人 AI 调度与 Airtap 进度机制；只有真实调度缺口才增加独立服务。
5. 事件内容按已授权 AI 分发；撤销后停止交付和自动执行。云端不默认保存通知正文或把全部用户内容集中成公共记忆库。

### 第三优先：内容流转和常见系统动作

为真实任务补可查询、可核验的窄接口，例如受支持的日程/闹钟 Intent、媒体控制或指定类型的文件发布。每个动作明确参数、当前支持条件、实际结果和 UI 回退，不增加无边界的任意 Intent/文件路径执行器。

在已有文件和媒体接口上优先完善：类型与大小检查、回传进度、断点恢复、选择器可见性、实际接收方和文件一致性。它们能同时改善写材料、发图片、录音理解和视频制作。

### 后续专项：实时音视频、系统级能力和其他设备

实时视觉需要独立评估端到端延迟、码率、耗电、长连接恢复和停止语义；不能由上传一段 MP4 宣称已经实现。电话对话、传感器、配件和 iPhone 也分别验证真实 API 与设备条件。暂时没有硬件或使用方的适配保持候选，不以抽象插件体系替代具体用途。

## 5. 怎样证明“能用”

以下是建议的任务集。它用于选择最有价值的验证，不是本轮新增的全部发布门槛；当前均不因列在这里而视作通过。

| 类别 | 候选验证 | 结果断言 |
| --- | --- | --- |
| 观察与输入 | ①无树弹窗选择；②长列表找目标；③长按拖入文件夹；④多指缩放后返回 | 点中正确目标、没有误触下层窗口；目标元素或文件夹实际存在 |
| 内容与文件 | ⑤图片写入相册并选中；⑥PDF 跨 App 分享；⑦大文件断点恢复；⑧中文/emoji 长文编辑重开 | 接收方可读取、类型/字节一致、正文未截断、未重复写入 |
| 业务结果 | ⑨岗位筛选表；⑩报销汇总；⑪同规格比价；⑫内容草稿或按授权发布 | 事实来源可回查，最终产物可重开；“已发布/已提交”有对应状态 |
| 系统与事件 | ⑬日程保存和去重；⑭指定通知触发；⑮历史短信核对；⑯拨号/接挂的限定测试 | 时间/对象准确、事件只处理一次、短信范围明确、电话状态正确 |
| 媒体与硬件 | ⑰相机采集回传；⑱麦克风短录音；⑲无声录屏与时长；⑳智能插座充电闭环 | 文件实际可解码且内容对应；实体状态核对，音视频和通话范围不混淆 |
| 持续使用 | ㉑中途断网续办；㉒多 AI 互斥交接；㉓用户停止/撤销；㉔多日后台后再次使用 | 保留任务和配对、不重复外部副作用、停止后不自动恢复、实际完成下一次任务 |

每次记录实际 AI/工具版本、设备/系统、初始状态、最终结果、耗时、人工介入、失败与恢复。比较体验时优先看：整件任务完成率、每件任务需要的人类帮助、错误对象/重复提交、传输量与耗时、断线恢复时间。不能只比较点击速度，也不能把一次成功换算成长期成功率。

AndroidWorld 的原始环境要求与 Airtap 的最低 Android 版本不同。可借用“变动初始数据 + 最终状态断言”的方法，也可移植适合的任务；移植环境和任务后应报告为自己的评测，不冒称原基准榜单成绩。[AndroidWorld 运行说明](https://github.com/google-research/android_world)。

## 6. 产品取向

Airtap 应继续聚焦：**让用户现有的个人 AI，稳定使用已有的手机。** 大模型推理、个人记忆和云端工作流尽量复用；Airtap 把设备接入、观察与动作、内容交换、有效授权、恢复和交接做好。

云端接入、MCP、视觉点击、模型可替换都已有公开同类。更有说服力的差异是用户实际做到：用旧手机接入自己正在用的 AI，日常不用电脑连线，任务可以独立完成，出错能恢复，换 AI 能交接，且支持范围有真实证据。每一项都需要通过实际使用来兑现，不能只靠定位文案。

继续提高能力上限，同时减少完成同一件事需要用户做的步骤；以有价值的结果和可重复的使用体验决定下一项开发。
