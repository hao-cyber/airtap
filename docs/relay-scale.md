# 中继容量与本地负载检查

当前配置最多登记 1000 台设备。这个数字是准入上限；实际可承载的在线数、同时执行数、任务延迟和费用要分别测量。当前完成了本地真实 workerd 的 1000 台合成终端实验，未对公共中继压测，也未验证 1000 台实体手机或云端容量。

## 可复现入口

使用仓库锁定的 Node 依赖：

```sh
python3 tools/check.py --suite protocol --install-deps
node relay/service/tests/relay-scale.mjs --devices 1000 --concurrency 50 --rounds 5 --idle-ms 5000 --output dist/relay-scale/regular.json
node relay/service/tests/relay-scale.mjs --devices 1000 --concurrency 1000 --rounds 2 --idle-ms 1000 --output dist/relay-scale/burst.json
```

协议套件默认只运行 24 台、并发 12、每台 2 条 `ping` 的短测。后两条为单独的容量实验。程序不接受目标 URL；所有请求进入临时本地 workerd，结束后关闭连接、销毁进程和临时 SQLite 文件。设备上限 1000、每台命令上限 10、并发上限 1000、空闲观察最多 10 秒，整轮有 180 秒期限。超限参数在创建本地服务前拒绝，失败也输出结果和清理情况。

实验通过生产 HTTP 接口真实登记、生成邀请、申请及批准，再保留原授权迁移到多 AI 模式。每个合成终端建立一条 WebSocket、确认握手，随后申请任务、顺序完成若干 `ping`、释放并核对空闲。手机替身只回复合成状态和任务屏障 ACK，不执行 Android 操作。协议、鉴权、序列及存储由生产代码处理；计数器只存在于本地夹具中。

每台合成设备使用文档专用网段中的不同 IP，符合现有每 IP 登记限制；这不能验证单一出口的大规模登记。局部拒绝检查覆盖登记达到上限后不写存储、另一设备的控制凭据不能读状态或发命令、主动撤销后不能取得任务，也不能偷偷发出手机命令。

## 记录与判断

[2026-11-03 实测记录](results/relay-scale-local-20261103.json)保留源码与工具摘要、环境、各阶段延迟、成功数、写入次数及清理结果。登记、配对、连接、状态、活跃任务和最终空闲分别记录；`ping` 另有单命令延迟，任务吞吐包含申请与释放时间。峰值任务数是客户端实际收到 `ready` 后尚未释放的数量；峰值未完成命令数是客户端请求数，不是 Android 同时操作数。

| 本地实验 | 在线连接 | 活跃任务峰值 | 成功 `ping` | `ping` P95 | 含申请/释放的命令吞吐 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 常规并发 | 1000 | 50 | 5000 / 5000 | 92 ms | 702 / 秒 |
| 同时突发 | 1000 | 1000 | 2000 / 2000 | 1023 ms | 463 / 秒 |

两个 1000 台实验分别采用 50 和 1000 并发。这两次测量中，增加并发主要增加了排队延迟，未获得同倍吞吐提升；它们是在共享开发机上的单次样本，不能据此给出稳定性能上限。登记后的目录约 278 KB；1000 台初次登记累计 2000 次整表保存，应用层序列化字节合计约 285 MB。配对及命令阶段没有重写登记整表，而是逐设备写用量。这里的字节数不等于磁盘写入或 Cloudflare 账单；本地持久化文件占用也不等于云端计费存储。

本地测试使用单一进程、回环请求和即时回复，没有公网 RTT、图片编码/传输、真实手机延迟、多地域路由或云端 CPU/配额约束。不能据此宣布公共中继支持 1000 台同时执行，也不能直接按本地吞吐估算每个真实任务耗时。当前测量没有出现需要变更已配对设备状态才能解决的失败，因此本轮不改线上存储布局。

## 隔离云端实验的预算

下一轮必须使用独立 Worker 名称、Durable Object 命名空间、服务身份和合成凭据，不复用公共服务绑定。建议先 10 台、再 100 台，确认失败率、P95、队列与额度后再进行 1000 台；从云端指标核对真实 CPU、DO 请求/时长和 SQLite 读写。固定最多 1000 个设备对象、1 个目录对象、1000 条连接、10000 条小 `ping`，不传图片。达到时间、请求或费用预算即停止并删除测试资源。

1000 台正常初始化还受当前每 IP 每日 20 次登记限制。先准备合法的测试身份，或另审隔离测试部署的限流设置；不能伪造真实边缘的 `CF-Connecting-IP`。若测试部署改变该限制，必须记录差异，不能把结果当作生产注册限流验收。现有本地脚本没有远程执行开关。

下列价格于 2026-11-03 查阅官方页面；未核对维护者账户的实际套餐、剩余额度或账单，也没有变更套餐：

- Workers Free：每日 10 万请求，每次 10ms CPU；Paid 为账户最低每月 $5，含每月 1000 万请求与 3000 万 CPU ms，超额分别 $0.30/百万请求、$0.02/百万 CPU ms。WebSocket 初次升级算请求。[Workers 价格](https://developers.cloudflare.com/workers/platform/pricing/)
- SQLite DO Free：每日 10 万请求、13000 GB-s、500 万行读、10 万行写，总存储 5 GB；Paid 包含每月 100 万请求、400000 GB-s、250 亿行读、5000 万行写及 5 GB-month。超额请求 $0.15/百万、时长 $12.50/百万 GB-s、行写 $1/百万，行读 $0.001/百万，存储 $0.20/GB-month。休眠合格时不计时长，入站 WS 消息按 20:1 折算请求；RPC、alarm 也计请求，alarm/删除会写行。[DO 价格](https://developers.cloudflare.com/durable-objects/platform/pricing/)

按当前调用结构，1000 台一次准备、两次全量状态、一次任务申请/释放及 10000 次 `ping`，约有 20000 次 Worker 请求、68650 次 DO 计费请求等价量；最后一项包含握手/屏障/命令回执的 WS 折算，不含额外重试、alarms 和清理。注册和每次请求都会产生内部 RPC，不能仅按 10000 次业务命令算请求费。应预留请求及存储余量，实际账单以云端指标为准。

作为上界场景，若 1001 个对象在整段 10 分钟都无法休眠，按官方示例的每对象 128 MB / GB 换算，时长为 `1001 × 600 × 0.128 = 76876.8 GB-s`，超过 Free 单日时长额度。它按超额单价线性折算约 $0.96，但**不是发票估算**：还要扣月包含量，并按官方计费单位向上取整；该段若使已有超额时长跨入一个新的百万 GB-s 单位，会增加 $12.50。不能许诺这轮测试一定免费或不到 $1。若 Paid 包含量仍足够，对应维度可以没有新增用量费用，但基础月费和其他资源仍分别计算。

需要控制在 Free 时，应先核对账户共享余量，再缩短并发在线窗口。例如全部对象不能休眠的 60 秒是约 7688 GB-s；它只是时长预算，并不能证明请求、写行和 CPU 也足够。当前生产代码采用休眠 WebSocket API，但本地通过不证明云端实际休眠比例。不得为了免费测试占尽其他服务的共享额度。

## 后续扩容与回收

当前 `MAX_DEVICES` 配置校验最高为 1000，不能只把部署参数填成更大数字。单一 AdmissionRegistry 仍处理目录解析与逐设备计数；扩大在线并发会让这些请求汇集在一个对象。SQLite 单键和值合计限制为 2 MB，不能无限扩大整张目录。[DO 限制](https://developers.cloudflare.com/durable-objects/platform/limits/)

1. **先处理登记写放大，再按实测拆分热点。** 可将目录条目与每日登记统计分开持久化，保持同一目录对象内的原子配额；后续按稳定的设备 ID 路由分片。每设备的控制对象、URL、原授权和命令序列不变。全局登记上限、每日限额和每 IP 限制不能各分片重复发放。迁移须有固定版本、幂等进度、旧写入停止点和失败恢复，不能让新旧计数同时放行。测试要覆盖迁移中断、旧请求迟到、停止及重启；未通过前不调高公开上限。
2. **不根据“没有当前配对”清除设备。** 当前历史记录不能证明设备从未批准过 AI；撤销后的设备、离线手机、正在配对的手机都不能据此误删。未来需要在手机状态中原子记录不可回退的 `ever_approved`，历史未知视为需保留；只从正常设备鉴权更新活动时间。自动过期政策应先在新登记的客户端/服务声明，当前 `enrollment_expires_at: null` 不应被悄悄改成会失效。
3. **回收顺序必须防止旧授权复活。** 只对超过已声明期限且确定从未批准的记录，携带预期世代/活动版本，在设备对象内再次核验没有有效邀请、授权、任务或在线连接，先持久化终止状态，再释放目录容量及用量记录。配对、活动、停止与回收竞争必须由条件检查决定；未知结果沿同一意图核对，不能删后重建原 ID。现有反馈 alarm 也要与回收调度合并，不能被覆盖。旧配对、永久身份与停止语义在迁移测试中单独核验。

这些是具体待实现项，本轮没有自动回收接口、目录分片或线上扩容部署。1000 台本地结果、隔离云端容量结果和公共服务运营承诺分别维护。
