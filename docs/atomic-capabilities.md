# Airtap 手机操作能力清单（2026-10-27）

目标是让个人 AI 在机主授权和平台允许的范围内使用手机，尽量补齐人操作手机所需的观察、输入、文件与设备接口。**本清单持续补充；列出某项不代表已经实现，更不代表所有 App 和设备已经通过验收。**

本文记录 **Android 0.4.0-beta.8 / code38、CLI.8**。连续触摸、输入、语义控件、音量、窗口、文件传输、分页观察、长文本、跨 App 文件分享及旧 SAF 暂存回收已有实现；当前推荐已更新为 beta.8/code38。主机 helper、实际 workerd / CLI / MCP 协议、Android 模拟器、实体手机和个人 AI 是不同验收层次，不能互相代替。

当前分页、长文本、分享和回收的主机／协议／模拟器证据见第 11 节；code37 补充分页语义元数据一致性。code38 另加入证书验证加固、邀请内文件校验信息、通知恢复和首次接入恢复修复，已有整合检查、[模拟器升级与恢复](results/beta8-code38-recovery-20261027.json)及 [Muse 原配对 WPS → 便签真机回归](results/beta8-code38-muse-20261027.json)。具体失败、维护升级和未验范围保留在记录中。code36 已由维护者在全新模拟器走正常安装、权限和核码，经公共中继用生产 CLI 完成 Clock → Files → Clock；有环境修复和人工准备，不是独立新用户或个人 AI 验收。

Muse 的已验范围仍绑定历史安装包：[code34 限定原子能力回归](results/beta6-code34-muse-20261027.json)包括一次完整翻页拖放、双指触摸、编辑、音量和 36 字节文件往返，保留拖动取消及唤醒失败恢复；[code35 真实跨 App 任务](results/beta6-code35-muse-demo-20261027.json)完成浏览器查阅、便签保存重开和回桌面，另有[短时屏幕保持](results/beta6-code35-physical-screen-20261027.json)。这些历史结果不自动覆盖后续版本。另有 [code37 静音真机回归](results/beta7-code37-muse-20261027.json)：原配对、自动唤醒、806 字符／812 UTF-16 单位四段回读及测试便签保存重开通过；[首次协议获准后的补验](results/beta7-code37-muse-followup-20261027.json)确认 WPS 展示 52 字节文本、小红书搜索与前八条可见路线详情、抖音两屏六条结果列表、191 字便签保存重开；抖音详情未完成，保留权限提示未响应点击及 Muse 返回恢复的记录。首轮协议阻碍和魅族便签空白导入仍保留；这些结果绑定 code37，不覆盖 code38。**用户不满意现有视频，视频交付暂缓，旧 80 秒剪辑不算已验收成果。**

## 1. 三个层次

| 层次 | 内容 | 怎样验收 |
| --- | --- | --- |
| 原子能力 | 观察状态、指向目标、触摸轨迹、节点操作、编辑输入、系统导航、文件或硬件接口 | 输入准确、作用目标准确、结果可观察，失败和停止语义明确 |
| 业务任务 | 安装 App、登录、搜资料、发消息、付款、分享文件、拍照上传 | 由个人 AI 组合动作；验证最终结果、授权范围及人工介入，不能只看 `accepted:true` |
| 系统身份与真实物理动作 | 指纹、人脸、物理接触、插卡、移动镜头、接线、按坏死设备的硬件复位键 | 按系统认可的本人验证或真实硬件条件完成；软件触控不能冒充物理事实 |

“安装”不是一种触屏动作，“支付”也不是一种通用系统 API。它们通常可由已有 UI 动作组成；能否完成还取决于页面、账号、安装来源、系统交互、网络以及必要身份验证。能力缺口应记录为待实现或待验事项，不改写成一律禁止的产品规则。

## 2. 状态含义与证据

- **已有实现**：已有 Android/中继/CLI 路径；已验范围仍以对应验收记录为准，不自动覆盖本表所有用途。
- **新增代码，真机待验**：代码与局部测试已完成；不等于已进入用户 APK，也不等于 Muse 验收通过。
- **适配中**：并行开发正在处理，不能预先写成已完成。
- **UI 路径可尝试**：可以组合现有观察和输入与 App/系统页面交互；不表示该完整任务已实测，也不表示已有专用接口。
- **待实现接口**：当前未提供对应原生数据/控制协议；说明合理后续方向。
- **需要实体条件**：必须有相应硬件、外界场景或本人身份验证。模拟器和测试桩不能代替这些事实。

整合范围包括连续拖动、多指时序、全部触摸动作的停止处理、26 种语义控件操作、输入编辑与 IME 会话绑定、系统动作、显式音量控制、窗口清单，以及范围内的文件发现、传输、状态恢复与 `file_share`。各测试的数量与结果以对应报告为准，避免把较早版本的测试总数作为新版本证明。协议检查实际运行 workerd、Python CLI 和 MCP，手机由模拟连接代替；另行记录的模拟器执行器验收也不等于小红或 Muse 真机通过。

## 3. 观察、窗口与目标定位

| 能力 | 当前实现/状态 | 可用替代与待补范围 |
| --- | --- | --- |
| 在线、授权、息屏/锁屏/可操作状态 | 已有 `ping`、恢复状态和重连诊断 | 在线不等于 UI 可操作；系统身份验证、暂停、撤销须分别处理 |
| 当前前台应用、窗口 | 已有 `foreground` | 窗口分支补明确来源、display/rotation；当前 root 为空不能误操作下层窗口 |
| 屏幕截图 | 已有默认屏 JPEG `observe`，短期 observation_id、实际尺寸与归一化坐标 | 受保护画面、截图失败应如实返回；不承诺连续视频流或受保护内容 |
| 屏幕录制与录屏回传 | 系统录屏 App/快捷设置的正常 UI 路径可尝试；Airtap 尚无专用连续录屏回传接口 | code35 演示由维护者采集真实录屏，不证明 Airtap 已有录屏接口。系统 UI 采集、文件访问和回传仍需分别验证；开发取材工具不算产品能力，也不能绕过受保护画面 |
| 界面结构 | 已有 `read_tree`、node_id、位置/类型/文本/可操作状态、密码遮蔽；非敏感文本附真实 UTF-16 长度与截断标记 | 首页文字仍最多200 UTF-16 units；新增 `read_node_text` 按原快照分段回读，`read_tree_page` 遍历后续页，均不续期；2,048节点/2MiB完整扫描预算超限明确拒绝。新接口的主机、协议与模拟器证据见[分页观察记录](results/paged-observation-20261027.json)；code37 另将 range、动作标签/集合、collection、编辑器与无障碍焦点等已导出元数据纳入分页一致性比较，[17 项主机检查](results/paged-metadata-host-20261027.json)通过，真机尚未触发分页续读和元数据变化反例；code37 Muse 已验分段长文回读。code35 便签重开树只有标题、字数和空白编辑节点，正文通过完整截图核验；WebView/自绘内容不能只依赖树 |
| 节点与图片新鲜度 | 已有 snapshot/observation 有效期、包名/窗口/旋转/边界校验 | 新鲜引用不保证页面未动画或用户未移动内容；动作前后仍须观察 |
| 多窗口、输入法、系统对话框清单 | 已有窗口清单与 default display 活动 root 回退；code34 Muse 实测 `android` 系统选择器的窗口、树与返回 | 精确接受合法系统包 `android`，不放开任意单段包名；不自动 Back，不猜底下 App 就是当前目标。其他系统窗口仍可能只暴露元数据 |
| 指定窗口/副屏读树、截图和输入 | 待实现；本轮窗口清单不包含任意 window_id 选择或副屏控制 | 发现副屏不等于支持其操作；需独立坐标与观察绑定 |
| 刘海、系统栏、键盘、分屏、悬浮窗、缩放 | 现有截图按实际默认屏像素映射；部分窗口元数据适配中 | 明确 inset/可触范围、放大手势、TalkBack 和分屏组合仍待测；不能按截图外观猜坐标 |
| OCR、视觉理解、页面语义判断 | 由用户的个人 AI 使用截图/界面树完成 | Airtap 提供证据；没有额外内置模型/OCR 成功保证 |

Android 提供窗口枚举和截图能力，但内容可见性、截图保护与交互窗口是否暴露需分别判断。[AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[FLAG_SECURE](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SECURE)。

## 4. 触控、持续拖动与多指

| 能力 | 当前实现/状态 | 可用替代与待补范围 |
| --- | --- | --- |
| 单击、长按、直线滑动 | 已有 `tap`/`long_press`/`swipe`，已统一到可中断执行器；旧动作及新增触摸的已验范围按版本记录 | 保持 60ms 点击、700ms 长按、100–5000ms 滑动请求语义 |
| 先按住再拖动 | 新增 `drag`：按住 → 沿路径移动 → 停留 → 释放，同一次手指接触 | 不能用“先长按抬手、再滑动”冒充连续拖动 |
| 拖到边缘停留、翻页后继续拖 | `drag` 可用重复点表示停留，再继续路径 | code34 Muse 在测试靶以 `gesture` 完成 3123ms 单次接触、翻页和 DROP；此前 `drag` 的 1532ms CANCEL 仍为失败。其他桌面/App 的翻页耗时和落点须分别实测 |
| 双击、三击、多段点按 | 新增 `gesture` 可表示多个有间隔的接触轨迹 | 使用真实抬手间隔，按目标 App 阈值验证；不是连续 hold |
| 曲线路径、画线、手写形状 | 新增 `gesture` 支持分段线性轨迹，可近似曲线 | 路点数量和时长有当前工程上限；没有压力、倾角、笔尖类型等保证 |
| 双指缩放、旋转、双指拖动 | 新增多轨 `gesture` 可同步移动多个指点 | code34 Muse 的双指 709ms 链具有完整 POINTER_DOWN/POINTER_UP/UP 且无 CANCEL；这不代替地图、图库或游戏的缩放/旋转业务结果 |
| 多指不同时间按下/抬起 | 新增轨迹的 start_ms 和各自终点，可保留其他指点连续性 | 当前至多 min(10, Android stroke limit) 轨、每轨 32 点、整段 10 秒；是可调整工程约束 |
| 手势停止、撤销、断线和用户抢占 | 新增执行器按最多 100ms 的注入段检查授权、命令有效性、包名和几何；停止后只清理仍按住的指点 | 100ms 是段时长，不是墙钟 SLA。已执行部分无法回滚；释放可能触发 drop/click，返回结果不确定并重新观察 |
| 按下后跨多次远程请求保持、根据新观察再决定下一段 | 当前未提供跨请求的开放式 pointer session | 当前单次完整路径可覆盖许多拖动；在线反馈式持续接触需超时、失联释放、独占和撤销设计 |
| 压感笔/悬停/鼠标右键/滚轮/触摸板/物理按键组合 | 不由当前触屏轨迹接口提供 | 语义 context_click 或 UI 菜单可覆盖部分目的；真实输入设备特性需独立适配/实体硬件 |

Android 手势派发会与其他输入产生取消关系，也可能受系统放大、触摸探索影响。本轮伪平台测试验证了指点连续与清理逻辑，不能替代设备产生的 DOWN/MOVE/UP/POINTER 证据。[dispatchGesture](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#dispatchGesture(android.accessibilityservice.GestureDescription,android.accessibilityservice.AccessibilityService.GestureResultCallback,android.os.Handler))。

## 5. 语义控件操作

| 能力 | 当前实现/状态 | 可用替代与待补范围 |
| --- | --- | --- |
| 点击、长点击、向前/后滚动 | 已有节点动作，部分支持向可操作祖先回退 | 若无有效语义节点，可在新截图上触控；不能把返回 true 等同最终业务成功 |
| 聚焦、清除焦点、选择/清除选择、上下文菜单 | focus 来自新增 input；其余在 `ce78da5` 的 `node_action` | 只执行节点实际声明的动作；没有语义声明时可尝试正常触摸路径 |
| 无障碍焦点、清除无障碍焦点 | 已有代码；与普通输入焦点分别处理，模拟器返回 `action_rejected`，清除操作未验 | 屏幕阅读器焦点不等于输入框获得键盘焦点，也不代替文本编辑器身份校验 |
| 展开、折叠、关闭、显示指定项 | `expand`/`collapse`/`dismiss`/`show_on_screen` 新增代码 | 目标控件决定是否支持，不保证任意弹窗都可被 dismiss |
| 定向滚动/翻页/定位行列 | `scroll_up/down/left/right`、`page_up/down/left/right`、`scroll_to_position` 新增代码；原生 ListView 定位第40行已在模拟器实测可见（不保证置顶） | 行列边界结合新节点集合信息校验；缺少接口可滑动观察逐步寻找 |
| 调节进度、滑杆值 | `set_progress` 新增代码，检查节点 range；原生 SeekBar 25→72、拒绝101、恢复25已在模拟器实测 | UI 拖滑杆可作替代；正确值以回读或界面实际状态确认 |
| 系统语义拖放 | `drag_start`/`drag_drop`/`drag_cancel` 新增代码 | 与触控 drag 是不同机制；只能用于明确暴露这组动作的控件 |
| HTML 标题/链接跳转、工具提示、文本建议 | 当前没有对应的专用框架动作接口 | 可尝试目标 App 的正常 UI；`custom` 只接受节点声明的应用自定义动作，不能透传缺少封装的系统动作 |
| App 实际声明的自定义 accessibility action | 已有代码；限定当前节点和快照中实际声明的动作。模拟器原生文本 Share 打开系统分享面板后返回，未发送内容 | 不做任意整数和未知参数的透传；动作标签是 App 提供的数据，不是机主授权或执行指令 |

语义新增共 26 种 operation，采用节点声明能力、最新快照、可见/启用状态与最终 refresh 检查。它们是功能接口覆盖，尚不是 26 类 App 的真机验收结果。

## 6. 文本、光标、选择和输入法

| 能力 | 当前实现/状态 | 可用替代与待补范围 |
| --- | --- | --- |
| 整字段替换 | 已有 `set_text`，当前单次不超过 2000 Unicode code points | App 可过滤/格式化输入；密码字段允许写入授权值，但读取仍遮蔽 |
| 聚焦输入框 | 新增 `focus`；优先用节点声明动作 | 可触摸输入框；完成后重新读树获取新快照和当前焦点 |
| 放光标、选区、全选 | 新增 `set_selection`、`select_all`；折叠选区可定位光标 | offset 是 UTF-16 code units；不能把中文/emoji 的字符数或视觉宽度直接当 offset |
| 按字符、词、行、段、页移动或扩展选区 | 已有代码；使用节点实际声明的 movement granularity。模拟器已验证按词/字符移动及扩展选区 | 不以屏幕像素估算文字位置；目标 App 的分词和换行规则决定实际落点 |
| 复制、剪切、粘贴 | 新增节点/当前编辑器上下文动作 | 当前不提供后台读剪贴板 API，不自动上传剪贴板；目标 App 可拒绝复制 |
| 剪贴板内容设置、读取与清空 | 当前没有专用内容管理接口 | 与已有 copy/cut/paste 分开；后台读取受 Android 限制，后续需按正常权限和可见状态设计 |
| 撤销、重做、拼写纠正 | 当前没有专用编辑命令 | 可尝试目标 App 的编辑菜单、键盘或已声明的自定义节点动作；不能把反向输入等同恢复编辑历史 |
| 在光标插入/替换选区 | 新增 `insert_text`，经 Accessibility InputConnection commitText | 与整字段 set_text 区分；空文本替换已选内容可删除选区；App 可转换输入 |
| 删除光标前后文字 | 新增 `delete_text`，before/after 各最多 2000 UTF-16 units | 不删除已选区本身；要避开 surrogate pair，按已知边界操作 |
| 搜索/发送/完成/下一项/上一项 | 新增 `editor_action`：default/done/go/next/previous/search/send | default 使用实际 app IME action；显式 send 可能真的提交内容，须具备对应任务授权 |
| 输入法候选、组合文本、语音输入、软键盘切换 | 没有专用 composing/candidate/voice 接口 | 可尝试观察键盘后点按；正常输入接口不是实时模拟每个键，不承诺保留任意 IME 候选行为 |
| 任意硬件键码/快捷键/全局 Ctrl 组合 | 当前没有通用键盘注入 | 节点动作、IME action、输入框与键盘 UI 可覆盖部分目的；后续独立适配 |

输入接口绑定新节点、焦点、窗口与编辑器包名；InputConnection 调用是异步派发，必须观察结果。独立审阅发现同包编辑框切换时，包名校验不足以排除旧 IME 连接；`c8b3d3` 已追加真实资源 ID、EditorInfo.fieldId、焦点节点与 IME 代次的绑定；后续修复在会话开始时锚定同窗口唯一资源字段，待实际焦点确认后才签发输入票据，解决正常焦点延迟，同时保留陈旧/歧义字段拒绝。23 项输入 helper 及模拟器跨字段插入、删除、SEARCH/DONE 已通过；code34 Muse 又核对 secondary 编辑、DONE 及 primary 未变。无法确认身份时应明确返回 `editor_identity_unavailable`，仍可使用节点实际声明的直接操作。同包快速切换、陈旧连接和无资源名等反例不能由一次正常编辑代替；不得写成“绝不会输入错框”。官方说明 selection/deletion 使用 Java char 单位，删除还需避免割裂代理对。[AccessibilityInputConnection](https://developer.android.com/reference/android/accessibilityservice/InputMethod.AccessibilityInputConnection)。

2026-10-27 后续修正增加无资源名节点的原生全选回退，并在读树中将占位提示与已输入文字分开；隔离模拟器已验证 Unicode 全选、严格 IME 仍拒绝、空提示与同名正文区分。此补丁已纳入后续 code34/35；code34 Muse 正常编辑回归没有覆盖无资源名节点的全选回退。节点默认 IME-enter 的实测回调为 `IME_NULL`，不能当成显式 `DONE`；应用最终结果须另行确认。详见[补充验收](results/node-select-all-20261027.json)。

code31 的 Muse 实测发现，插入末尾文字后直接删除会删到更前面的内容。隔离 Android 模拟器用实际 InputConnection 重现了相同结果：输入法保留的组合范围改变了原生 `deleteSurroundingText` 的边界。后续实现检查输入法与节点选区是否一致；组合范围会改变删除边界、或尚无法确认组合状态时，本次删除不派发，并提供“新树 → 明确选择实际要删的范围 → 新树 → 空文本替换选区”的恢复步骤。不会自动点 DONE 或把未确认的编辑重放。45 项输入 helper 及真实模拟器的拒绝、精确恢复、保留原选区的两侧删除、普通删除通过，见[组合输入删除验收](results/composing-delete-20261027.json)。code34 Muse 真机回归已将末尾 XYZ 正确删除并提交 DONE，原始事件与树一致；这一轮走普通原生删除分支，未触发组合范围拒绝，也未实测显式选区恢复，不能把它写成这些分支的 Flyme 验收。

## 10. 身份、授权与真实物理边界

这三类问题必须分开，避免把工程缺口当作系统禁令，也避免宣称触控可以替代机主：

| 情况 | 正确处理 |
| --- | --- |
| 机主已授权的普通确认、任务继续、选择内容 | 在授权范围内由 agent 代办，记录真实代理操作；不因出现“确认”按钮重复打扰机主 |
| 系统明确要求本人身份验证，或确需指纹/人脸/设备凭据的状态 | 使用系统支持的验证流程；不能假冒本人或把已授权普通 App 输入说成解锁身份验证。首次接入集中准备，远程状态准确说明 |
| 新增账号授权、发送、付款、删除等具体后果 | 根据已有明确任务授权执行；缺少授权时再确认动作和内容。应用级控制许可不能自动判断每一次业务后果 |
| Airtap 自己的授权/停止/撤销界面 | 远端不得替机主扩大自己的授权；授权撤销不能自动恢复。可离开页面，不可点击批准控件 |
| 手机被关机、没电、拔线、插卡、插附件、相机需要移动、NFC 需要靠近 | 标明物理条件；可由预先部署的硬件/网关提供后续能力，但当前手机客户端不能凭软件制造物理条件 |

Android 会区分锁屏状态和是否需要安全身份验证；唤醒屏幕或请求系统退出允许退出的锁屏不是绕过安全锁。[KeyguardManager](https://developer.android.com/reference/android/app/KeyguardManager)。

界面树累计字节预算修复 `49f74b4` 已纳入 code33 及后续 code34/35：即使最后一个已出队节点因预算被省略，也返回 `truncated:true`。最后节点省略、正常完整树与仍有排队节点的定向主机反例已通过；code34 普通树读取不等于在真机触发过大树边界。历史封包 code32 未被同号替换。

屏幕保持修复 `7de6157` 从 code35 开始：原先只在 60 秒锁已超时后才重取，存在两秒检查周期内的续租间隙；现在只在同一授权代次且屏幕已亮、已解锁时提前续租。10 项完整服务时间测试和隔离模拟器跨两次 60 秒边界、主动息屏及本地停止检查通过，见[屏幕续租验收](results/screen-lease-renewal-20261027.json)。没有新增主动唤醒标志，也不改变停止/撤销路径。后续 code35 真机 80.168 秒的 67 次只读电源采样均为 Awake/持锁，录屏在该窗口后才开始；采样不能证明每个瞬间或多日稳定。缺少 code34 失败时对应的电源原因记录，仍不能据此断言那次 CANCEL 就由该问题引起。

## 11. 验收闭环与后续顺序

每一个新增接口都要通过同一闭环：**发现能力 → 绑定当前目标/授权 → 执行动作 → 观察实际结果 → 可停止/撤销 → 网络或系统变化后如实恢复**。不以动作数量或列出的 App 数量评价完成度。

| 顺序 | 验收对象 | 所需证据 |
| --- | --- | --- |
| 1 | 合并输入、语义、窗口与统一手势后编译，校验手机/中继/CLI 请求一致 | 发布构建身份和协议测试记录 |
| 2 | 测试靶验证连续 hold/drag/边缘停留/落点、双击、多指、停止/断线；旧点击/长按/滑动回归 | 测试 App 的原始 DOWN/MOVE/UP/POINTER 链与结果，不能只用维护者截图 |
| 3 | 双编辑框验证光标/UTF-16 选区/插入/删除/IME 搜索与完成、快速切换焦点和陈旧连接拒绝 | 测试 App 的合成文本、selection 和 InputConnection 事件；不输入私人内容 |
| 4 | 真实窗口/安装器/输入法/通知栏、语义 slider/列表等代表性场景 | 当前包/窗口/显示器、实际操作及结果；无 root 时不误操作下层 App |
| 5 | Muse 从实际云端用原配对完成至少一个跨 App 真实任务与失败恢复 | 云端请求、手机变化、最终结果、失败和人工介入全部留证；USB 只用于诊断/取证 |
| 6 | 文件工作目录、系统文件夹授权、双向校验、重试、已有文件保护、停止与撤销 | 协议替身、真实 Android 本地 provider 和实体手机分开留证；中途创建未知不能冒称成功 |
| 后续 | 在线反馈式持续触摸、副屏、更多跨 App 接收方验收及媒体/硬件接口按实际任务优先级逐项补齐 | 每类独立证据，不把模拟器或 UI 推测写成真机支持 |
