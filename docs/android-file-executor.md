# Android 文件执行端

这一实现补充 `files_v1` 的 Android 执行端。接口、CLI 与个人 AI 使用方法见[个人 AI 接入说明](agent.md)；接口存在、编译或 host 测试通过不代表某台手机或 DocumentsProvider 已通过验收。

默认的 Airtap 工作目录是**当前配对专用的 App 内部目录**，与凭据、偏好、反馈及其他 App 私有目录分开；它不是“下载”目录，其他 App 不能直接找到其中的文件。Android 的内部文件目录无需新增存储权限。[Android 官方说明](https://developer.android.com/training/data-storage/app-specific)。

机主可在“设置 → 文件访问”通过系统选择器选择一个文件夹，允许当前 AI 读取，并在实际取得写权限且提供者支持新建时放入文件。它是可选步骤，不增加默认接入步骤。Android 11+ 不允许直接选择存储根目录、下载根目录、Android/data 或 Android/obb 等范围；可在“下载”内新建“Airtap文件”子文件夹再选。授权来自持久 URI grant，root 标识不暴露 URI 或原始设备路径。[SAF 官方说明](https://developer.android.com/training/data-storage/shared/documents-files)。

系统选择器打开期间，远端不能执行手机操作。每次选择使用独立、本地一次性的 requestCode 与配对身份；回到 Airtap 时取消未完成尝试，旧选择器的迟到回调不能扩大权限。更换 AI、文件夹、撤销 URI 权限或服务停止都不会继续旧授权下的文件命令。文件读取/写入在后台线程进行；每块和发布之前回到主线程检查当前命令、配对、锁屏、Airtap 授权窗口与范围代次。

## 接收与发布

上传使用调用方生成的 transfer_id。相同 ID 的规格必须一致；相同块的重试必须匹配已落盘字节。每块最多 4 KiB，当前单文件最多 8 MiB、最多 4 个未完成上传；工作目录最多保留 128 份传输记录，SAF 最多保留 128 份未回收传输记录；暂存与结果回执的逻辑有效期为 24 小时，内部清理随后续访问触发，不保证到时立即释放磁盘。过期 SAF 私有暂存会在后续访问时跨配对回收；未知外部创建的身份记录保留，见下文。这些是首版请求预算和存储约束，不是长期产品能力上限，也不能据此称为 APK 安装通道。请求序号仍须递增；操作结果未知时先查 transfer 状态。

- **工作目录：`publication_atomic:true`。** 完整 SHA-256 校验后，先持久化 committing 日志，再在 App 私有工作目录的全局 IO 锁内核对目标不存在并执行同文件系统原子重命名。该目录没有其他 App 写入者，本服务的并行请求不能覆盖已有文件。同步发布目录和完成日志后完成清理。进程在发布后中断，可通过已知暂存 inode 确认结果；不能把同名但不是同 inode 的文件猜成成功。目录 fsync 使用 Android 正常 `Os` API；host 故障注入不代替实体断电验证。
- **授权文件夹：`publication_atomic:false`。** 先在 App 内完整接收、校验，再记录 creating 状态并新建文档。取得创建结果后立刻保存该文档 ID，之后仅对这个文档写入并回读校验。中途可见不完整文件，不承诺提供者原子提交。恢复时重用记录的文档，不重新创建；名称冲突或提供者改名不冒称请求路径已写入，可明确 abort 删除已记录的新建文档。
- **创建结果未知：`commit_unknown`。** 如果系统可能已创建文档但尚未保存其 ID，禁止猜测、新建第二份或删除疑似同名文件。保留状态，请检查授权目录。SAF 回执过期后也不能自动把同一未知提交当成新的上传。停止或权限撤销后，未完成的外部文档可能留在所选目录；只有仍有有效范围且确知由本上传创建的文档可经 abort 清理。到期自动清理只处理内部暂存，不根据名字猜测删除外部文件。

`finished` 是提交回执。用户随后删除或修改目标文件不会改写历史结果；客户端应重新 stat 并比较当前大小与完整 SHA-256。下载按块检查偏移、版本与块 hash，并对整份内容与 stat 的 SHA-256 比较。元数据版本不能独自证明内容未变化。

遇到 `commit_unknown`，AI 可先在原授权目录执行 `file-list`，再对预期文件执行 `file-stat`，比较大小和完整 SHA-256。这只能确认目录中当前存在的内容，不能证明某个同名文件由这次未知上传创建，也不能把未知提交回执改称成功。若提供者改名、存在多个候选或无法核对，应保留未知状态并说明具体差异；不要再次创建或删除猜测的文件。

原始文件内容不加入诊断日志；中继仅通过现有鉴权命令通道转发。一般文件移动、目录创建、任意删除尚未由这组命令实现；workspace 已增加下述受限跨 App 分享，可继续组合已授权的 UI 操作，后续分别补齐结构化能力。SAF 的读写/新建/删除标志与具体提供者行为须实际发现与验证，不把它们视为任意路径访问。[DocumentsContract](https://developer.android.com/reference/android/provider/DocumentsContract)。

## Android 执行器验收（2026-10-27）

隔离的 Android 16 手机模拟器使用本地真实 Workers 执行器和生产 CLI，保留原配对，完成了以下维护者验收：

- 工作目录：10,506 字节多块二进制文件、中文与 emoji 文件名的上传和下载，整文件 SHA-256 一致；零字节文件、同 ID 重试、不覆盖已有文件通过。
- 系统 SAF：通过系统选择器在 Download 下新建测试子文件夹并授权，实际 DocumentsProvider 新建写入、回读校验和下载通过；返回 `publication_atomic:false`。授权由维护者在系统界面操作，不记为个人 AI 自动授权。
- 中途中断连接后保留已收的 4,096 字节，恢复连接后先查状态，用同一个传输 ID 完成；重复块没有重复追加，abort 可重复调用。
- 选择器打开时远端命令返回 `file_authorization_in_progress`；撤销文件夹授权后旧 scope 被拒绝，私有工作目录仍可使用。将现有 Airtap 界面前置以取消选择，再回到旧系统选择器确认，旧结果没有建立授权。

实际 Android 测试暴露并修复了两个 host 测试无法证明的问题：`Files.getFileStore` 被系统拒绝，改为对自有目录调用 `File.getUsableSpace`；硬链接发布被应用沙箱拒绝，改为上述私有目录全局 IO 锁内的原子重命名。Android 上的目录 fsync、fileKey 身份与原子重命名均已随成功上传实际执行。38 项 host 文件系统、恢复状态机和授权生命周期测试通过；不据此宣称实体设备、OEM 后台、云端文件提供者或真实断电持久性已验证，也不替代 Muse／Instinct 的完整任务验收。

## 本地回收与私有容量

机主可在「设置 → 文件访问」查看占用，选择「清理文件… → 清理工作文件」并确认；尚未配对也能进入此入口。清理涵盖当前和历史配对的 App 私有 `workspace`、对应传输暂存与回执，不改配对、设备登记、SAF 授权或共享文件夹原文件。SAF 的内部暂存和创建日志也保留，避免丢失外部未知创建结果的身份。成功上传的文件不会被静默按 TTL 删除。中途失败明确显示未全部完成，可再次清理。

当前工程预算为文件通道中全体配对共 **256 MiB 私有逻辑文件字节加剩余上传／日志预留**，不是每个配对单独额度。`file_roots.limits` 返回预算、已存字节、预留字节及 `all_pairings` 范围。新传输前计入声明大小；每块增长前重新核对，覆盖旧配对、孤儿暂存、SAF 内部文件及未建完内部传输的 SAF receiving 日志。同一传输已写字节从剩余预留扣除，不重复计算；重复 begin 不再单独预留。手机共享文件夹原文件、App 安装包及鉴权记录不计入此文件通道预算。预算控制新上传和块增长，不阻止读取、机主清理或已有发布的恢复。

同时检查 **16 MiB 设备可用空间余量**。逻辑字节与日志预留不是文件系统实际分配量，其他 App 的并发写入、系统或提供者错误仍可能导致存储不足；不承诺磁盘绝不写满。预算由 `PrivateFileStorage.BUDGET` 定义，维护者可据实调整和重新构建，当前没有普通用户额度滑块。SAF 未知创建的保留材料若占满预算，本地工作文件清理不会猜测删除它们，需要明确的后续恢复／管理流程。“清理工作文件”仍不删除 SAF 材料。另有“回收过期和旧连接暂存”入口：回收所有配对的过期 SAF 字节，以及以前配对的未到期暂存；当前配对未过期的上传保留。每次远端文件操作也会自动回收所有配对中已过期的 SAF 私有暂存。未知创建和已知文档的 publication journal 保留并标记 payload_reclaimed，先持久化标记再删除 payload，避免中断后被当作新上传。清理不调用外部 provider 删除接口；这些小型身份记录仍计入预算，不能宣称占用绝对归零。

所有文件 IO 与本地清理共用后台锁；确认清理先更新持久化文件 epoch，让旧命令失效，再在后台取得锁。主线程不阻塞等待持锁的文件线程。清理不跟随符号链接，失败不清空 SAF 创建日志。

本次生命周期增量通过 52 项 host 测试，并在隔离 Android 16 / API 36 模拟器以维护者方式完成：为历史配对放入 264 MiB 合成工作文件，确认全局预算拒绝新上传；在真实 App 界面查看占用、确认清理，验证当前与历史工作目录清空，SAF 内部日志、目录授权（文件 epoch 除外）、共享目录文件内容及原配对保持不变，随后新上传成功。最终界面再次清理并重复核验。未配对入口有代码及空存储 host 覆盖，未在该已配对模拟器撤销配对做完整界面验证；本记录不代表实体手机、真实掉电或个人 AI 任务验收。


## Workspace 跨 App 分享（本轮增量）

`file_share` / CLI `file-share` / MCP `phone_file_share` 接收 `root:"workspace"`、相对 `path`、最新 `file_stat.version`、具体 `mime_type` 和 `target_package`（空字符串为普通系统分享单）。只允许一个已发布工作文件；不接收任意 URI、绝对路径、Intent、额外参数、写权限或持久权限。指定包须符合 App 包名和 Airtap 自身授权页保护规则；目标是否接受相应 MIME 由 Android 实际解析确认。请检查**手机** `file_share_v1` 能力，不能仅凭中继支持就推断旧 APK 可用。

手机生成随机短期 content URI，交给 Android 正常分享界面。Provider 不导出，仅通过系统授予所选接收 App 对这一 URI 的临时读取权；最多 5 分钟、最多 16 个活动分享。分享绑定当前配对、文件 epoch、运行会话和文件版本。URI 不回传给 AI；协议只返回 `share_id` 和有界元数据。当前实现不把 `accepted:true`、`chooser_requested:true` 当作选择收件人、发送或接收成功，AI 必须继续观察目标 App 并核实任务结果；提交仍依据机主对内容和目标的授权。

文件通过 Android proxy 文件描述符按最多 4 KiB 的块读取，每次读前后检查临时权限与当前配对/会话/epoch；每块只核对 inode/大小/修改时间和相对路径，不重算整文件哈希。停止、撤销、清理 workspace、更换文件范围、进程死亡或期限到达后，后续打开和已打开描述符的后续读取被拒绝，系统 URI grant 同时撤销。无法收回接收 App 已复制或已读入缓存的字节，不能将此机制称为阅后即焚。

`file_share` 走相同的正常唤醒、锁屏身份验证、命令期限、停止和自身授权窗口检查。打开分享单不允许远端操作 Airtap 的授权界面。系统分享 UI、不同接收 App、MIME、厂商与版本仍需分别验收。使用分享不改变默认 workspace 对其他 App 私有的性质；通用 mkdir/复制/改名/移动/单文件删除及大文件传输仍是独立后续能力。

## SAF 回收后的恢复语义

过期或旧连接的 payload 清除后，`receiving` / `writing` / `verifying` 变为对外 `expired`，不能重新接收字节、继续发布或用相同 ID 重新创建。若有确切已创建文档 ID，`cleanup_required:true`，在当前文件夹授权有效时显式 abort 只可删除这一个记录的文档。`creating` 仍为 `commit_unknown`，不会猜测删除或重建。`finished` / `aborted` 的历史结果保留；仍需 stat 确认现在的外部文件。被回收的记录不再预留上传字节或完整日志预算，不占活动上传/未回收记录数；剩余身份记录的实际字节仍计入总容量。

当前代码新增了过期 unknown 身份保留、已知文档定向 abort、活动传输保留、跨旧配对回收后重新接收、孤儿年龄边界、符号链接拒绝和清理中断恢复测试。结果以本轮验收记录为准；不将测试替身或模拟器结果写成实体手机／Muse 的新能力验证。
