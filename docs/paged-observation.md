# Stable UI pages and long text

The Android companion adds two read-only commands, advertised by the **phone** as `paged_tree_v1` and `node_text_v1`. A new relay or CLI does not upgrade an older APK. These commands use the same original pairing, scope, screen readiness, selected foreground window and protected Airtap-surface checks as other observations.

`read_tree` creates a snapshot and returns its first page. `nodes` is bounded to 128 entries and 56,000 serialized node bytes; the byte limit may produce fewer entries. `total_nodes` is the exact number of visible, same-package nodes in the completed capture; `total_inspected_nodes` also counts hidden nodes. `traversal_complete:true` means the bounded native traversal completed, **not** that a virtualized list exposes offscreen content. Follow `next_offset` until it is null. `offset`, `returned_nodes` and `truncated` describe this page. IDs are stable within this snapshot, including later pages.

```sh
python3 airtap.py read-tree
python3 airtap.py read-tree-page --package com.example.app --snapshot-id SNAPSHOT --offset NEXT_OFFSET --limit 128
python3 airtap.py read-node-text --package com.example.app --snapshot-id SNAPSHOT --node-id NODE --field text --offset 0 --length 4096
```

Use actual values from the preceding response. The direct API uses `read_tree_page` or `read_node_text` plus the normal UUID and sequence. MCP exposes `phone_read_tree_page` and `phone_read_node_text`; both have `readOnlyHint:true`.

A page request requires `package`, `snapshot_id`, `offset` (0–2048) and `limit` (1–128). It rescans and compares native node identities, traversal order/topology, visibility, complete text field fingerprints and all exported node metadata before returning the cached page. The separate page metadata fingerprint includes range values, collection dimensions, advertised actions and labels, editor metadata and accessibility focus; object key ordering does not change its value. This does not widen the more tolerant identity used for ordinary node actions. A changed tree requires a new `read_tree`. The first capture is checked twice so inconsistent captures are not published. No continuation extends the original 30-second deadline. The CLI retains already advertised node IDs when receiving another page, allowing later-page nodes to be operated on normally. Every action still consumes its original snapshot.

A text request requires `package`, `snapshot_id`, `node_id`, `field` (`text`, `description`, or `hint_text`), `offset` (UTF-16 units) and `length` (2–4096 UTF-16 units). The response returns the selected field in `text`, with `offset_utf16`, `length_utf16`, `total_length_utf16`, `next_offset_utf16`, `eof` and `offset_unit:"utf16"`. Always use the returned next offset: the chunk may end earlier to avoid splitting a surrogate pair. An offset inside a surrogate pair is rejected as `invalid_text_boundary`. An empty value or exact end offset yields an empty EOF chunk. Combining characters may cross chunk boundaries; concatenate exact chunks before displaying the whole value.

Text is read only from the original visible native target. Its full text, description and hint fingerprints and normal node identity must match before and after capture. These fingerprints remain local to the snapshot; no text digest is returned or persisted. The original window, package, authorization, transport and deadline are checked again before returning content. Disabled but visible non-password text may be read; mutation eligibility remains unchanged. Showing-hint editors return empty `text` and their advertised `hint_text`. Password nodes return `sensitive_input` with no content, length or digest. Changes after the last platform check remain possible: this is a checked observation, not a lock on another App.

On `stale_node` or `fresh_snapshot_required`, discard the incomplete assembly, get a new tree and restart the field. Do not concatenate chunks from different snapshots, node IDs or fields. Calling `read_tree` again, performing an action, window changes, stopping/revoking or disconnecting invalidate the old observation. Tree pages intentionally require broader stability than a node action; unrelated dynamic content can require another tree without proving the target itself is unusable.

Capture is bounded to 2,048 inspected native nodes, 2 MiB of cached identity/metadata and a 5-second scan budget. `inspection_limit` or `inspection_incomplete` returns **no snapshot, partial total, or misleading continuation token**. For such screens, use a screenshot and authorized navigation/scrolling to narrow the visible content, then observe again. A WebView or custom canvas that does not expose its text cannot be repaired by pagination. Long documents whose chunks cannot finish within the original deadline still need a different supported App export/file path; the API does not silently extend authorization freshness.

Validation is recorded in [the observation result](results/paged-observation-20261027.json). Helper tests, actual local workerd/CLI/MCP and an Android emulator are separate evidence. They do not claim an independent user, a physical device or Muse has accepted this new API.

A later focused consistency review found that range/action/collection metadata was not included in the original page identity. The separate metadata fingerprint fixes that gap without changing ordinary action-target freshness. [17 host checks](results/paged-metadata-host-20261027.json) include range, custom-label and action-set changes, plus unchanged metadata and all original cases. [Six native Android checks](results/paged-metadata-native-20261027.json) verify a range-only 10→11 change rejects an old continuation while a fresh page exposes 11; every other exported field stayed unchanged. These are production-source helper/native observations, not personal-AI or physical-phone acceptance.
