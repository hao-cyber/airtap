# Airtap 0.4 完整手机体验

2026-10-25：按用户要求采用统一新版协议 v4，不为旧客户端保留产品模式。现有登记身份可保留，但旧会话不能自动扩大权限；首次新版连接由机主确认完整手机授权。

## 验收目标

- 普通用户无需电脑、命令行、模型 API key、中继地址配置；提供预配置安装包与逐步系统授权引导。
- 核码批准一次自己的 AI，默认完整手机读屏和操作，取消逐 App 勾选、15 分钟会话和 200 命令限制。
- 配对与递增命令序号持久化；正常断网、进程恢复、锁屏再解锁不要求重新配对。停止/撤销先落盘，不能自动恢复。
- App 目录、前台识别、节点动作、长按、基于最新截图的坐标点击/拖动、返回/主页/最近任务；结果须重新观察，未知动作不得自动重放。
- HTTP API 与 Python CLI/标准 MCP 适配共用协议；无品牌绑定。实际客户端能力仍须逐一验证。
- 手机保留停止/解除连接入口；保护自身授权界面，遵守系统锁屏与安全窗口边界。

## 2026-10-26 开放能力与远程使用补充目标

- 用户决定任务，个人 AI 负责思考，Airtap 尽量提供完整设备能力；不把现有动作清单、示例 App 或当前缺口固化为永久产品限制。
- 默认设备不在机主身边。首次接入集中准备必要设置，之后优先自动亮屏、处理无需身份验证或系统已允许退出的锁屏，并恢复正常连接；停止或撤销后不得自动恢复。
- `0.4.0-beta.3`区分息屏、锁屏和确需系统身份验证的状态，提供 `ping` 状态查询及授权 GUI 请求触发的恢复；`ping` 本身不唤醒。本轮交付新增能力，不更改此前验收结论；实际变更回归另行记录。
- 恢复后清空旧截图和节点快照，取得新画面再继续任务；失败返回具体原因和下一步，不能一概要求机主到场，也不能将动作请求被接受当成已完成任务。
- AI 自行选择工具路线和处理配对恢复；普通用户只处理必要的系统设置、核码及缺失的任务决定，不反复确认 CLI/HTTP 等实现选项。
- 对用户已授权的应用登录提供密码框输入，读屏仍遮蔽密码；网页导航支持合法 HTTP/HTTPS、局域网地址、IP 与端口，不将当前只接收公网 HTTPS 的实现固化为产品规则。对应客户端与中继须一起验证，应用输入不等同于系统锁屏身份验证。
- 验收增加实际息屏自动恢复、无需认证的锁屏恢复、系统认证状态反馈、旧快照失效、断网恢复和停止后不恢复。分别记录设备、版本、实际任务与人工帮助；模拟器通过不等于所有远程设备均支持。

- 系统要求身份验证而拒绝命令时，明确该次设备操作未执行，不保留待验证后自动重放的命令；验证后 AI 重新观察并决定后续动作。操作后补读失败须与动作执行结果区分。
- 本轮魅族 Note 16 的后台入口已核对，但开启后台许可后的最终息屏任务尚未验证通过；不将权限开关或在线状态视作已解决 OEM 后台恢复。
