# Disposable Android native multi-AI checks

This opt-in harness runs all production Android Java and resources, real Android Keystore / accessibility / SAF Binder calls, and the actual local workerd implementation. It does not replace `PreviewService`, `TaskLease`, `FileScopes`, `TlsPolicy`, or execution gates. It never contacts the public service.

`prepare.py` copies the candidate into a private build directory and records all production Java SHA-256 values. Test packaging uses a distinct application ID, disables shrinking, adds an app-local synthetic CA and two explicitly synthetic owner-driver components. The CA is the test package's only trust anchor. `relay.mjs` exposes real local HTTPS/WSS and accepts private controller requests via stdin; it contains no fake phone. `run.py` requires the specifically named disposable AVD and refuses to overwrite existing packages unless its own installation marker exists and `--reset-created` is explicit.

Use a **new, disposable, rootable Google APIs AVD**, not a physical phone or a pre-existing user emulator. The installed SDK must contain API 36 / build-tools 36.1.0; the current preparation template uses a Pixel 5 definition. A private rootable arm64 system-image path can be passed with `--rootable-system-image`. Run `prepare.py --help` and `run.py --help` for required paths. Keep build outputs, certificates, controller credentials, receipts, screenshots and reports outside the repository. Start the new AVD with the name `Airtap_Multi_20261031` on an unused port. The runner checks this name and `ro.kernel.qemu` before any installation. It uses root adbd solely to bind its loopback reverse port 443; non-root Play Store images reject that binding. No system trust change is made.

The owner driver calls the actual consent persistence and recovery methods using synthetic claims. OS accessibility and notification permissions are enabled via ADB only in this new emulator. This is **not** human-facing owner UI, normal first-user onboarding, OEM lifecycle, or personal-AI acceptance. The separate target APK logs real `MotionEvent` delivery and implements a real DocumentsProvider with a controlled slow query. The slow provider and synthetic owner decisions are test inputs, not substitutes for production grant checks.

The harness retains failures. A successful result must have `complete: true` and each named check passing. Do not infer a pass for a later check when an earlier one blocked it. In particular, Android `JSONObject.put(key, null)` removes a key, unlike an explicit `JSONObject.NULL`; native storage validation must not be bypassed or rewritten in the test to make migration succeed.

After collecting evidence, uninstall only the two packages created by this harness, remove its reverse-port mapping, return HOME, stop the newly created AVD, and delete only that AVD registration. Preserve private failure evidence and source hashes. The runner currently leaves the disposable environment available for failure diagnosis; cleanup is an explicit final owner step.
